## 摘要

本工作面向初赛的人类撰写文本与机器生成文本二分类任务，输出机器类别概率 `p_machine`。我们以字符级 TF-IDF 与类别均衡逻辑回归建立 CPU 轻量基线，以 XLM-R 主模型提供主预测，并在两者同一内部 dev 预测上复核预先固定的概率融合。

在 `internal-v2` 的 15,086 条 dev 样本上，字符 TF-IDF 基线的全体宏 F1 为 0.946766、临时短文本宏 F1 为 0.918468、临时综合分 S 为 0.938276；XLM-R 512-token、seed 43、2,000 次有效更新终点的对应值为 0.945575、0.956943、0.948986；固定 `0.7×基线 + 0.3×主模型` 融合为 0.968463、0.953381、0.963939，总错误 440 条。上述均为同一 dev 的内部开发结果，阈值为 0.5，短文本按空白计词少于 100 的临时口径；融合权重来自更早的 dev 探索。独立接收方已报告 0.5 分类决策一致，但主模型与融合分量在原逐点容差下分别有 274 条和 4 条超限，数值验收差异仍待双方闭环，因此当前方案尚未冻结。内部 test 与官方验证集均未用于本轮开发、调参或评估。

## 1. 任务与方案概览

初赛任务是对输入文本判断来源类别：人类撰写（human，标签 0）或机器生成（machine，标签 1），并输出机器类别概率 `p_machine`。本文讨论来源检测，不判断文本事实真伪；复赛涉及的生成器归因和人机混写片段定位不属于本文当前实验范围。

方案包含三条相互衔接的技术路线：

1. **数据与评测底座**：固定清洗、分组和约 80/10/10 划分，统一宏 F1、短文本宏 F1、综合分 S 与预测 CSV 口径。
2. **轻量基线**：字符 n-gram TF-IDF 特征加类别均衡逻辑回归，作为 CPU 对照与互补信号。
3. **主模型与固定融合**：XLM-R 二分类微调；在同一 dev 上复核 `0.7×基线 + 0.3×主模型` 的概率加权，并核对错误互补性。

全流程使用同一固定数据划分，不自行重新切分。所有比较只在 train/dev 上进行；内部 test 在方案冻结前保持封存，官方验证集只允许在冻结后做最终推理。

## 2. 数据与评测

### 2.1 数据来源、清洗与固定划分

原始训练文件为赛题方提供的 `data.jsonl`，大小 980,438,954 字节，SHA-256 为 `a4d8d012f10ee57110473e06cfdda648fc64643eef72e97e4ef3b818ba727d98`。该文件在仓库中保持不变，所有处理均输出到独立版本目录。

预处理读取 95,889 条记录，展开实际文本字段和评审列表；仅在文本确实以相应提示词开头时剥离提示词（219 条）；过滤少于 20 个字符的文本（human 7,101 条、machine 93 条）；按来源标识和规范化正文去重（human 72,136 条、machine 14,074 条），并对机器文本按生成器与正文去重。最终得到 149,895 条样本、33,083 个分组。

`internal-v2` 采用 seed 42 的 group-based 约 80/10/10 划分。本文开发实验只使用 train 和 dev：

| 集合 | 样本数 | Human | Machine | SHA-256 |

| Train | 119,842 | 43,922 | 75,920 | `5a5dca9db706e0faadc5c89cbcadc77dc585ce302f5e73b11b82213f40ab7ff6` |

`internal-v2` 修复了 `internal-v1` 中 5 条人类评审展开正文跨 train/dev 重复的问题。v2 在分组阶段把所有将被导出的规范化正文绑定到 `group_id`，并在写出时逐条实测：三集合两两 `group_id` 交集和规范化正文交集均为 0。本文使用的 train/dev 字节数、样本数与 SHA-256 均与版本 manifest 一致。

数据来源与许可：原始数据由赛题方提供，本文不声称拥有或重新许可该数据；数据使用、再分发和提交范围受赛题规则约束。具体条款仍由数据负责人对照赛题规则确认并在最终提交前记录。

### 2.2 指标与评估协议

使用全体样本二分类宏平均 F1，以及短文本子集宏平均 F1。综合分定义为：

```text
S = 0.7 × MacroF1_all + 0.3 × MacroF1_short
```

本轮开发使用阈值 0.5，即 `p_machine >= 0.5` 判为 machine。短文本按空白分词数量小于 100 计数，dev 中共有 1,841 条短文本，占 12.2%。题面已明确 `<100` 词边界和 S 公式；尚未说明的是多语言计词的具体实现、概率转类别的最终规则以及提交 CSV 的准确模板、编号对应和类别方向细则。因此本文的空白计词只是内部临时口径，不能称为已确认的官方多语言口径。

本文所有标为“临时”的指标均为 `internal-v2` dev 上的开发结果，不是官方验证集、隐藏测试集或内部 test 成绩。内部 test 未参与模型训练、调参、评估或融合选择；官方验证集未用于文本探查、统计或调参。

## 3. 方法

### 3.1 字符级 TF-IDF 与逻辑回归基线

基线使用字符级 TF-IDF，n-gram 范围为 2–5，`min_df=2`，最多保留 300,000 个特征，特征矩阵使用 `float32`；分类器为 `C=1`、`max_iter=1000`、`liblinear` 求解器的逻辑回归，并使用 `class_weight="balanced"` 缓解类别不平衡。随机种子为 42。

TF-IDF 词表、IDF 和分类器参数仅在 train 上拟合；dev 只用于预测与开发评估。模型输入只有正文，不使用 `sample_id`、`group_id`、`generator` 或 `domain` 作为特征。CPU 训练耗时约 530.635 秒。模型文件为 11,931,952 字节，SHA-256 为 `6d231819e61d24b2f9b8ee91b07b72f6e7c0f8c26d93c500d419d791211c46f8`；保存的类别顺序为 `[0, 1]`，machine 为类别 1，因此 `predict_proba(...)[:, 1]` 即 `p_machine`。

该模型由 Python 3.14.0、NumPy 2.4.6、scikit-learn 1.9.1 和 joblib 1.6.0 序列化。训练时工作树存在未提交改动，运行元数据记录了基线启动版本，但未记录执行源码指纹；当前 `baseline/run.py` 的 SHA-256 `c722f96e6500b0361d25ebaa53813f70b7dad802643717f37bb227cdba692416` 只能标识当前推理实现，不能冒充训练时的精确源码。该限制在最终提交中继续披露。

### 3.2 XLM-R 主模型

主模型使用 `FacebookAI/xlm-roberta-base`，固定 revision 为 `e73636d4f797dec63c3081bb6ed5c7b0bb3f2089`。模型以正文为唯一输入，不输入编号、生成器或领域信息；分词后按最大长度截断，推理时进行批内填充。machine 概率取二分类 logits 经 softmax 后的类别 1 分量。

正式开发比较采用单 GPU、batch size 1、梯度累积 16、学习率 `2×10^-5`、AdamW、weight decay 0.01、最大梯度范数 1，使用恒定学习率、无学习率调度。训练启用 FP16 与梯度检查点，数据加载 `num_workers=0`；分类头、编码器 hidden 及 attention 的有效 Dropout 概率均为 0.1。长度对照比较 256 和 512 token，并在 seed 42、43 下各完成 2,000 次有效优化器更新。每个 seed 的 512 实验均从固定原始预训练模型重新开始，先执行 50 次有效更新的资源检查，再恢复同一轨迹至预定终点；500、1,000 和 2,000 次更新处评估 dev，1,500 次更新仅保存检查点。该轮使用无加权交叉熵。

训练恢复保存模型、优化器、FP16 scaler、随机数状态和样本游标，并绑定数据、配置及源码指纹。512 两 seed 终点均完成 2,000 次有效更新、2,004 次尝试，其中 4 次 FP16 跳步，实际处理 32,064 行次，约为训练集 119,842 行的 26.75%。256 终点处理 32,048 行次。该比值只反映处理量，不能视为已唯一覆盖相同比例的样本，也不能称为完整 epoch；512 与 256 的跳步位置和曝光量不同，长度对照不能解释为严格等暴露的纯长度因果实验。

训练硬件为 RTX4060 Laptop GPU。512/seed42 与 seed43 的累计活动训练时间分别为 2,265.124 秒和 2,509.749 秒，峰值 allocated 显存均为 5,772.785 MiB，reserved 分别为 6,078 和 6,080 MiB；该时间不包含全部评估、绘图与人工处理。终点单次保存前完整 dev 推理分别耗时 243.349 秒和 250.047 秒。训练环境记录为 Python 3.11.17、PyTorch 2.13.0+cu126、Transformers 4.57.6、Accelerate 1.15.0 与 NumPy 2.4.6。

统一推理使用 FP32、batch size 8 和 512 token。完整 dev 的统一入口实测：轻量基线推理 34.467 秒，主模型推理 244.087 秒，主模型推理峰值 allocated 为 1,232.797 MiB。该推理资源与训练峰值分开报告，不互相替代。

### 3.3 概率融合

对轻量基线与主模型的 machine 概率进行固定加权：

```text
p_blend = 0.7 × p_baseline + 0.3 × p_main
```

融合在概率空间进行，不在 logits 空间进行；主模型输入为 512-token、seed 43、2,000 次更新的固定终点。该权重来自更早的 256-token 开发阶段：当时在 dev 上以 0.1 为步长比较 `w=0.1...0.9`，0.7 为最优点。512-token 复核按预先固定的 0.7/0.3 计算，没有重新搜索权重、阈值或校准器；本轮也没有训练新的校准器。内部分类统一使用 `p_machine >= 0.5`，最终提交应保留概率并按正式模板适配。

由于权重是在同一 dev 上选择的，融合结果具有同 dev 选择偏差。后续的组级 bootstrap 区间以已拟合模型和同一 dev 的选择为条件，不能消除该偏差，也不覆盖训练 seed 不确定性。

## 4. 实验结果

### 4.1 单模型比较

| 模型 | 全体宏 F1 | 临时短文本宏 F1* | 临时 S* | human 误报 / machine 漏报 | log loss | Brier |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 字符 TF-IDF + 逻辑回归 | 0.946766 | 0.918468 | 0.938276 | 319 / 428 | 0.187654 | 0.047532 |
| XLM-R 256 / seed42 / 2000 | 0.902358 | 0.910128 | 0.904689 | 1,145 / 161 | 0.320412 | 0.074418 |
| XLM-R 256 / seed43 / 2000 | 0.892437 | 0.943283 | 0.907691 | 1,334 / 85 | 0.302945 | 0.077047 |
| XLM-R 512 / seed42 / 2000 | 0.916560 | 0.931234 | 0.920962 | 1,008 / 113 | 0.345425 | 0.066888 |
| XLM-R 512 / seed43 / 2000 | 0.945575 | 0.956943 | 0.948986 | 561 / 188 | 0.169904 | 0.041883 |

\* 短文本为临时空白分词数 `<100`；阈值为 0.5。所有数值均为同一 `internal-v2` dev 的内部开发结果，不是官方成绩；2,000 次更新也不是完整 epoch。

字符 TF-IDF 基线在全体宏 F1 上略高于 512/seed43（0.946766 对 0.945575），也高于两个 256-token 终点；但主模型 512/seed43 的短文本宏 F1（0.956943 对 0.918468）和临时 S（0.948986 对 0.938276）更高。主模型 512 相对同 seed 256 的全体宏 F1 提升为：seed42 +0.014202、seed43 +0.053138；临时 S 提升为 seed42 +0.016273、seed43 +0.041295。两项提升均伴随明显的 seed 间波动，不能只报告较优 seed。

### 4.2 固定融合比较

| 融合候选 | 全体宏 F1 | 临时短文本宏 F1* | 临时 S* | human 误报 / machine 漏报 | log loss | Brier |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 0.7×基线 + 0.3×主模型 256/seed43 | 0.961422 | 0.949922 | 0.957972 | 385 / 149 | 0.164633 | 0.039957 |
| 0.7×基线 + 0.3×主模型 512/seed42 | 0.963726 | 0.940363 | 0.956717 | 348 / 155 | 0.156768 | 0.037675 |
| 0.7×基线 + 0.3×主模型 512/seed43 | 0.968463 | 0.953381 | 0.963939 | 240 / 200 | 0.148132 | 0.034057 |

512/seed43 固定融合相对旧 256/seed43 融合的临时 S 增量为 0.005967，总错误由 534 降至 440。按 dev 组配对 bootstrap（1,000 次，seed 20261016），S 差的条件 95% 区间为 `[0.230, 0.969]` 个百分点；该区间以同一 dev 上已拟合的模型和已选权重为条件，不消除选择偏差，不覆盖训练 seed 不确定性，也未做多重比较校正。

融合并非在所有分项上都优于单模型：512/seed43 融合的短文本宏 F1 为 0.953381，低于主模型单模型的 0.956943。因此报告保留该不利结果，不把融合写成全面改进。

### 4.3 错误互补与切片分析

在 512/seed43 终点上，轻量基线单独正确 569 条、主模型单独正确 567 条；两者都正确 13,770 条、都错误 180 条。固定融合总错误 440 条（human 误报 240、machine 漏报 200），低于基线单模型的 747 条和主模型单模型的 749 条。该互补性支持检验融合，但不能把同 dev 上选出的融合当作无偏性能估计。

轻量基线在全体 dev 上有 319 条 human 被误判为 machine、428 条 machine 被误判为 human。临时短文本子集中，1,841 条样本有 81 条 human 误报和 38 条 machine 漏报；短文本 human 召回率为 0.8451，低于 machine 召回率 0.9712。512/seed43 融合的 human/machine 召回分别为 0.956324 / 0.979147。

按领域切片的描述性结果中，`RuATD_2022`（1,202 条）宏 F1 为 0.8749，`PeerRead/iclr_2017/`（1,266 条）为 0.9009。生成器切片只包含 machine 单类，宏 F1 不适用；可报告漏报率，例如 `dolly-v2` 为 34/216（15.7%），`gpt-3.5-turbo` 为 130/2,660（4.9%），`text-davinci-003` 为 105/1,640（6.4%）。这些切片在当前 dev 上只作描述，不代表未见生成器、跨时间或跨域泛化能力。

### 4.4 概率质量与 seed 波动

延长训练的分类收益与概率质量没有同步改善。512/seed43 从 1,000 到 2,000 次更新，全体宏 F1 从 0.945235 变为 0.945575，临时 S 从 0.948830 变为 0.948986，仅增加 0.000156；log loss 从 0.154007 升至 0.169904，Brier 从 0.040248 升至 0.041883。这里保留预先声明的 2,000 次更新终点，1,000 次更新只用于诊断；不能仅凭训练损失下降断言继续加预算有效，也不能单凭上述现象判定过拟合机制。

两个训练 seed 的差异仍然明显：512/seed42 的 log loss 为 0.345425，明显差于 seed43 的 0.169904，尽管 seed42 的全体宏 F1 也低于 seed43。分类指标改善不等于概率校准改善，因此本文同时报告 log loss 与 Brier，并把概率质量列为独立局限。后续分类头 Dropout 0.2 等方案仅处于准备状态，没有实测结果，不替代当前候选。

### 4.5 跨环境加载与独立复现状态

轻量基线模型已在主模型的 Python 3.11.17 / NumPy 2.4.6 / SciPy 1.17.1 / scikit-learn 1.9.1 / joblib 1.6.0 环境中成功加载；对完整 dev 15,086 条预测无警告，`classes_=[0,1]`，与基线参考预测的最大绝对差为 `4.9996e-11`。本机统一离线包也已完成 smoke 与完整 dev 复核：主模型分量相对本机参考最大差为 0，基线分量约 `4.9996e-11`，融合分量约 `3.4997e-11`，0.5 分类决策均一致。

独立接收方在 CPU 环境按原逐点判据复算的结果如下：

| 检查范围 | 超限条数 | 最大绝对差 | 0.5 分类决策差异 | 状态 |
| --- | ---: | ---: | ---: | --- |
| 基线 full-dev | 0 / 15,086 | 5.000e-11 | 0 | 原容差内 |
| 主模型 full-dev | 274 / 15,086（1.82%） | 2.557e-05 | 0 | 原逐点容差未通过 |

## 6. 局限与讨论

1. **仅内部 dev**：所有结果依赖 `internal-v2` dev，不能替代官方验证集、隐藏测试集或内部 test 结果；未声称对新生成器、跨时间或跨域泛化。
2. **短文本口径临时**：`<100` 词边界已由题面明确，但多语言计词实现尚未说明；本文用空白计词，相关短文本指标与融合比较需在正式口径明确后统一重算。
3. **同 dev 选择偏差**：融合权重在同一 dev 上选择并报告；组级 bootstrap 区间以该选择为条件，不消除选择偏差，也不覆盖训练 seed 不确定性。
4. **训练覆盖不足**：2,000 次更新只处理约 26.75% 的训练行次，不是完整 epoch；唯一覆盖比例未知，不能把行次比例当成唯一样本覆盖率。
5. **seed 波动与长度混杂**：两个 seed 差异明显；512 与 256 的 FP16 跳步位置和曝光量不同，长度对照不是严格等暴露的纯长度因果实验。
6. **概率质量未同步改善**：512/seed43 从 1,000 到 2,000 次更新分类指标几乎不变，log loss 与 Brier 变差；分类改善不能写成概率校准改善。
7. **切片不是 OOD**：领域和生成器切片只作描述性错误定位；dev 包含已见生成器，不能作为未见生成器或分布外泛化证据。
8. **独立数值验收未闭环**：主模型 274 条、融合 4 条在原逐点容差下超限，虽然 0.5 分类决策全部一致；原因尚未独立证实，不能写成交付验收全部通过。
9. **源码追溯不完整**：基线与主模型的训练源码均存在未提交改动或历史指纹缺失；精确重训能力受限，需在最终报告中保留披露。
10. **数据许可待确认**：原始数据由赛题方提供，具体使用与再分发条款需按赛题规则确认；本文只记录来源与哈希，不自行给出许可结论。
11. **test/官方验证集未使用**：内部 test 仍封存，官方验证集未访问；最终一次 test 验收和官方推理须在冻结后按团队流程执行。早期预处理脚本曾在控制台打印各集合示例（含 test）；当前版本已将示例输出限制为 train/dev，本轮未读取或使用 test 正文。

## 7. 结论与当前状态

在固定 `internal-v2` dev 上，字符 TF-IDF 基线提供了有竞争力的 CPU 对照，并与 XLM-R 主模型存在明显错误互补。固定 `0.7×基线 + 0.3×主模型` 融合在 512/seed43 终点取得全体宏 F1 0.968463、临时短文本宏 F1 0.953381、临时 S 0.963939，总错误 440 条；但融合短文本分项低于主模型单模型，且权重来自同 dev 探索。

当前第一版候选为：`internal-v2` 数据、XLM-R 512-token/seed43/2,000 次更新、分类头 Dropout 0.1，与字符 TF-IDF 基线按 `0.7/0.3` 概率融合；阈值 0.5，输出保留 `p_machine`。该候选已经完成本机保存重载、统一入口和跨环境加载复核，但**尚未完成独立数值验收闭环与全队冻结**，因此本文仍是内部审阅稿，不是最终冻结版本。

后续次序固定为：

1. 独立接收方与主模型方按原容差公式完成数值差异闭环，确认是否需要修复或单独审议跨环境验收标准；
2. 全队确认数据、模型、融合和内部评测口径，记录第一版冻结版本与日期；
3. 冻结后由数据与评测流程执行**一次**内部 test 正式验收，结果用于验收与报告，不回流反复选参；
4. 轻量基线与报告维护方把 test 结果纳入同一报告，完成最终匿名 PDF、来源/许可证声明和提交材料核对。

在上述步骤完成前，不追加融合权重、阈值或校准搜索，不把 dev 分数写成官方成绩，不运行内部 test 或官方验证集。
